# 记账

一个**完全离线**的安卓记账 App。不联网、不申请权限、没有账号体系，数据只存在你自己的手机里。

安装包 **53 KB**。

> 现在的记账 App 大多要注册账号、要联网同步、索要一堆权限。这个不是——
> 它就是一个装在自己手机上的小工具，记完就完，不多做一件事。

---

## 特点

|  |  |
|---|---|
| **离线** | 不发起任何网络请求。断网、飞行模式照常用 |
| **零权限** | `AndroidManifest.xml` 里 `uses-permission` 数量为 **0**。不读通讯录、不读位置、不读存储 |
| **无依赖** | 界面与逻辑是原生 HTML/CSS/JS，没有框架、没有 npm 包、没有 Maven 依赖 |
| **不用 Gradle** | 直接用 Android SDK 命令行工具打包，十几秒出包（见[构建](#构建)） |
| **体积小** | APK 53 KB。同类应用通常 10 MB 起步 |
| **数据不出手机** | 存在 App 私有目录的 localStorage 里，App 自己都读不出来（除非 root） |

## 功能

### 记一笔

下半屏是记账区，聚焦金额框直接调起**系统数字键盘**。

- 金额、分类、日期、备注
- 分类点一下即选，记完**保留分类与日期**，方便连着记好几笔
- 保存只需**一次触摸**（见 [为什么保存要这样实现](#为什么保存要这样实现)）

### 流水

按日期倒序排列，每天显示当天小计。点任意一条可以编辑或删除（删除会二次确认）。

### 本月

收支汇总、**每日支出柱状图**、按金额排序的分类占比。左上角可切换月份。

### 攒钱目标

可以给想买的东西建一个目标（名称、目标金额、可选日期与图标）。

- **存入 / 取出**：每次记「这一次」存了多少、取了多少，已攒金额**自动汇总**
- 进度条、还差多少、完成百分比；达成后显示「已达成 🎉」
- **还需几个月**：按最近三个完整自然月的平均结余估算，跟随真实收支变化

**和记账的联动**：存入会在流水里生成一笔 `🏦 攒钱` 记录，取出生成 `📤 攒钱`，
但它们**不算真实消费**——不影响「本月支出 / 本月收入 / 结余」。

### 可支配金额

首页汇总条上多一个数字：

```
可支配 = 总余额 − 已攒合计
```

也就是「现在真正能动用的钱」。它**可能为负**（某个月存得比赚得多），这是正常的，不会截断成 0。

### 分类管理

预置分类不能删；可添加自定义分类（名字 + emoji）。

- 已被记录使用的自定义分类**不能删**，会提示有多少笔在用
- **▲▼ 调整顺序**，只在同一组内移动，到顶/到底时按钮变灰
- 调完顺序，记账页的分类条会跟着变

## 安装

**系统要求**：Android 5.0（API 21）或更高。

> 实测只在 Android 15 上做过完整验证。低版本理论上能跑（代码里对旧 API 做了分支
> 处理），但没有逐一测试过。

1. 到 [Releases](../../releases) 下载 `JiZhang.apk`
2. 手机上打开这个文件，按提示允许「安装未知应用」
3. 安装完成

> 使用 debug 签名，仅供侧载自用，不上架任何应用商店。

### 装不上时

| 现象 | 原因 |
|---|---|
| 「解析包时出现问题」 | 文件没下完，重新下载 |
| 提示「禁止安装未知应用」 | 到 设置 → 应用管理 → 找到你的浏览器/文件管理器 → 允许安装未知应用 |
| 小米/Redmi 提示风险 | 正常。选「仍要安装」，必要时先关闭 MIUI 优化 |

## 构建

不需要 Android Studio、不需要 Gradle。

**需要**：JDK 17+、Android SDK（build-tools 35.0.0 + platform android-35）、Python 3.x。

```cmd
tools\build.cmd
```

工具链位置默认是 `D:\android-jdk` 与 `D:\android-sdk`，可以用环境变量覆盖：

```cmd
set JZ_JDK=E:\tools\jdk21
set JZ_SDK=E:\tools\android-sdk
tools\build.cmd
```

细节（流水线各步、六个必须遵守的约束、每个工具做什么）见 **[tools/README.md](tools/README.md)**。

## 技术说明

### 为什么不用 Gradle

这个项目只有一个 Activity、四个前端文件，Gradle 带来的复杂度远超收益。
直接用 `aapt2 → javac → d8 → zipalign → apksigner`，构建十几秒完成，
而且**不需要联网下载任何依赖**。

### 为什么保存要这样实现

真机上踩过的坑：键盘弹起的瞬间如果先让输入框失焦，面板会立即回落，
**那一次触摸就点空了**——表现为「要按两次保存」。所以保存按钮：

- 用 `touchstart` 而非 `click`（早于焦点变化）
- `preventDefault()` 阻止后续默认行为
- 用时间戳去重，防止 `touchstart` 与 `click` 各触发一次导致**重复记账**

### 为什么键盘处理这么绕

**Android WebView 不把键盘高度暴露给网页层。** 实测在 Android 15 上：

- 键盘弹起时 `window.innerHeight` 与 `visualViewport.height` **恒定不变**（都是 915）
- 键盘收起时输入框**不会失焦**（`activeElement` 一直是那个 input）

两个后果：

1. 网页层算不出键盘高度，底部对齐的弹层会整张钻进键盘下方——用户能打字却点不到「确定」
2. 没有任何信号能知道「用户手动把键盘收起来了」，于是弹层会**卡在半空下不来**

解法是**由原生层上报键盘真实高度**（`MainActivity` 通过 `WindowInsets.Type.ime()`
取值，折算成 CSS px 后推给网页层），网页层再主动轮询这个值，
从而捕捉到「键盘被手动收起」的那一刻。详见
[docs/bug-savings-update-root-cause.md](docs/bug-savings-update-root-cause.md)。

## 代码结构

```
app/src/main/
├── AndroidManifest.xml          零权限
├── java/com/jizhang/app/
│   └── MainActivity.java         ~200 行：WebView 壳 + 键盘高度上报
├── assets/www/
│   ├── index.html                ~260 行：界面骨架
│   ├── css/app.css               ~790 行：配色变量 + 布局
│   └── js/
│       ├── store.js              ~560 行：数据层（localStorage 读写、统计）
│       └── app.js                ~1320 行：交互与渲染
└── res/                          图标与主题

tools/                            构建与调试脚本（见 tools/README.md）
docs/                             设计契约与踩坑记录
```

**数据约定**：金额一律以**整数分**存储（避免浮点误差）；日期用**本地时区**的 `YYYY-MM-DD`。

## 已知边界

- 使用 debug 签名，仅供侧载自用
- **没有导出/备份功能**。卸载 App 或清除数据会**永久丢失所有记录**，无法恢复
- 只在 1080×2400 @420dpi（Android 15）上做过完整验证，其他分辨率未逐一测试
- 「还需几个月」的估算基于最近三个完整自然月，**历史数据不足时会提示先记几笔**

## 开发过程

这个项目在实现过程中**每个功能都做了独立验证**，而不是"写完就算"：

- 数据层测试直接加载真实的 `store.js` 跑断言（`tools/test_savings_model.mjs`）
- 界面行为通过 Chrome DevTools Protocol 连到设备上的 WebView，**读页面真实状态**，
  而不是靠读代码推测（`tools/cdp_eval.mjs`）
- 键盘相关问题全部在真实模拟器上用**真实触摸**复现并验证

这条原则带来过实际收益：攒钱弹层"卡在半空下不来"这个问题，
光看代码是找不到的——必须实测才能发现**键盘收起时输入框不会失焦**。
